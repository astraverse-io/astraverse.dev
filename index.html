What we build

Three commitments, and we hold to all of them.

Operator tools ask for a lot of trust — cluster credentials, production access, the authority to change things. These are the rules we work under so that trust is reasonable rather than requested.

Your infrastructure, your credentials

Our software runs where you run it, using the access you already have. Nothing phones home. No cluster data crosses a boundary you did not choose — and when a third-party model is involved, you pick which one, or run it locally and pick none.

Open source, not open-core

Everything we make is Apache 2.0 and developed in public. Not a trial, not a crippled edition with the useful parts behind a sales call. You can read every command before it touches your cluster, because you can read all of it.

Show the work

An answer you cannot check is worse than no answer, because it is confident. Every conclusion our tools reach carries the evidence that produced it — the commands run, the output seen, the reasoning between them — laid out so you can disagree.

What we make

KubeAstra

Apache 2.0 Kubernetes MCP

An AI agent that investigates broken Kubernetes clusters. Ask it why a pod is crashlooping and it works the problem the way an engineer would — reading pods, events, logs and topology, following what it finds, and reporting a root cause with the evidence attached. It proposes fixes; you approve them. Write operations are gated behind an explicit confirmation, every time. It runs on your laptop against the kubeconfig you already have — nothing is installed in the cluster.
